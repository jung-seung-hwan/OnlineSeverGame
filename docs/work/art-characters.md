# 추가 캐릭터 (젤리곰·푸딩)

담당 세션: `[OnlineSeverGame] 캐릭터·맵 아트 · 02`
범위: 지금의 젤리 외에 고를 수 있는 캐릭터 후보를 추천하고, 사용자가 고른 젤리곰·푸딩의 콘셉트 시트를 만든다. Blender 모델·스프라이트, 게임에서 캐릭터를 고르는 기능(프로토콜 변경)은 사용자가 시안을 확정한 뒤 다음 단계.

## 1. 어떻게 보이게 되는가

- **젤리곰**: 지금 젤리와 같은 반투명 젤리 재질의 통통한 곰. 머리·몸이 한 덩어리(목·허리 없음), 머리 위 둥근 귀 두 개, 배 옆에 붙은 짧은 팔, 눈 아래 밝은 곰 주둥이. 장식은 두 귀 사이.
- **푸딩**: 컵에서 뒤집어 꺼낸 커스터드 푸딩. 아래 2/3는 곧은 옆면, 위는 좁아져 평평한 윗면, 윗면을 덮고 흘러내린 붉은 호박색 캐러멜. 젤리보다 광택이 덜한 부드러운 재질. 장식은 캐러멜 위.
- 둘 다 몸 색 = 플레이어 색(1장 표의 8색), 머리 장식 8종도 지금과 같다. 같은 캐릭터를 여러 명이 골라도 색·장식으로 구별된다. 캐러멜 색은 8명 모두 같다.

## 2. 왜 이 둘인가 (추천 과정, 2026-11-10)

추가 캐릭터가 지켜야 할 조건:
1. **판정 모양이 같아야 한다.** 위험물은 그려진 몸 모양 띠에 맞는다(`Shared/Simulation/HitShapes.cs`의 `Body`: 배 폭 1.02, 발쪽 0.78, 머리 쪽 0.52까지 좁아짐, 키 1.2). 그림이 이 띠와 많이 다르면 캐릭터마다 판정이 달라 불공평하다. 머리 장식은 판정에서 빠지므로 귀·꼭지는 자유.
2. **몸 색 = 플레이어 색, 장식 8종 유지**(색약 대비가 그대로 산다).
3. **위험물과 헷갈리지 않아야 한다**: 칼·고드름·눈덩이·나무 상자·마카롱. 순백, 네모 상자, 마카롱 모양은 피한다.
4. **동작 8종·시트 규격 그대로**(Blender 스크립트와 Unity 코드를 다시 쓸 수 있게).

추천한 후보: 1 젤리곰, 2 푸딩, 3 마시멜로(어깨를 둥글게 깎아야 함), 4 찐빵·만두(색 반죽만, 흰 반죽 금지), 5 무늬 껍질 달걀(판정은 가장 정확하지만 지금 젤리와 너무 비슷). 넣지 않기로 한 것: 각설탕·두부(창고 상자와 혼동, 모서리가 판정 밖), 마카롱(디저트 맵 위험물), 눈사람·흰 찹쌀떡(흰색이 칼·눈덩이와 겹침), 아이스크림콘(아래가 좁음), 경단 꼬치(판정보다 좁음). 사용자가 젤리곰·푸딩 시안을 골랐다.

## 3. 어떻게 만들었는가

기준 프롬프트(개인 파일, `.vibe-local/prompts/`, Git 제외)는 규칙 2에 따라 기존 기준에서 필요한 것만 바꿨다.
- `style-gummybear_v1.md`, `style-pudding_v1.md`: style_v2의 STYLE·8색 장식 블록은 글자까지 같고, **CHARACTER BASE만** 캐릭터별로 새로 썼다. 몸 비율은 지금 게임 몸(폭 1.0 × 키 1.2)에 맞춰 "키 = 폭의 1.2배, 배가 가장 넓고 머리 쪽이 폭 절반"으로 썼다. 젤리곰은 "머리·몸 한 덩어리"(목에서 판정보다 좁아지지 않게), 귀는 몸 키 12% 이하, 팔은 몸 윤곽 밖으로 거의 안 나오게. 푸딩 캐러멜은 칼 손잡이(#4A2A1A)와 헷갈리지 않게 붉은 호박색(#B4532A).
- `character-sheet-gummybear_v1.md`, `character-sheet-pudding_v1.md`: character-sheet_v2 브리프 그대로, 바꿀 수 있는 입력인 "기본형 색"만 바꿈(우윳빛 반투명 / 연한 바닐라 + 캐러멜).
- 생성: `codex exec -m gpt-5.6-sol --skip-git-repo-check -C D:/OnlineSeverGame - < 프롬프트.txt`. Codex 설정의 기본 모델(`gpt-6.1-terra`)과 `gpt-6.1-sol`은 ChatGPT 계정에서 "지원 안 함" 오류가 나서 이번 실행에만 `-m gpt-5.6-sol`을 붙였다(설정 파일은 그대로). Codex CLI가 0.158.0으로 모델 목록(0.167.0 기준)보다 오래돼서일 수 있다.

## 4. 생성물과 평가

모두 `Art/concept/`. 이미지를 직접 열어 보았고, 판정 띠를 변형 줄 8명 위에 겹쳐 봤다(배 폭을 1.02로 맞춰 축척, 발밑 = 바닥선. 검사용 이미지는 저장소에 넣지 않음).

| 파일 | 평가 |
|---|---|
| **character-sheet-gummybear_v1_01.png** | 곰으로 바로 읽힘(귀 + 주둥이). 반투명 젤리 재질이라 지금 젤리와 같은 세계. 8색 모두 어두운 배경에서 잘 보이고 장식이 두 귀 사이에 자리 잡아 귀와 겹쳐도 모양이 구별됨. 기본형 3면(게임 시점·정면·측면)이 같은 모양이라 모델링 기준으로 쓸 만함. **판정 띠 비교**: 키(귀 아래 머리 꼭대기)가 1.2에 맞고 배·발 폭도 맞음. 다만 머리·어깨가 둥글게 넓어서 높이 0.8~1.1 구간이 띠보다 좌우 약 0.05~0.1 넓다(그림이 판정보다 큼 = 칼이 스쳐 보여도 안 죽는 쪽). 팔이 몸 밖으로 조금 나옴. 기본형 3면은 변형 줄보다 조금 더 넓적함(세로:가로 약 1.15) |
| **character-sheet-pudding_v1_01.png** | 푸딩으로 바로 읽힘(캐러멜 윗면 + 흘러내림). 젤리보다 광택이 덜한 커스터드 재질이라 질감이 구별됨. 캐러멜은 중간 밝기 붉은 갈색으로 칼 손잡이보다 밝고 붉음. 8색·장식 구별 잘 됨(장식이 캐러멜 위에 올라감). **판정 띠 비교**: 아래 2/3은 띠와 잘 맞음. 평평한 윗면이 폭 약 0.72로 띠 꼭대기(0.52)보다 넓어 위 모서리가 좌우 약 0.1씩 띠 밖으로 나온다(프롬프트의 "윗면은 폭 절반"이 덜 지켜짐) |

종합:
- 두 시안 모두 캐릭터 정체성·8색·장식 구별은 기준을 만족한다.
- 남는 문제는 **머리 쪽이 판정 띠보다 넓은 것** 하나. 두 가지 방법이 있다.
  1. (추천) Blender 모델에서 머리·윗면을 판정 띠에 맞게 좁힌다(젤리곰은 머리를 조금 작게, 푸딩은 윗면을 폭 0.55 정도로). 그러면 세 캐릭터가 같은 판정을 쓴다. 이미지 생성은 정확한 수치를 못 지키므로 콘셉트를 다시 뽑기보다 모델에서 맞추는 편이 확실하다(맵 콘셉트 때와 같은 결론).
  2. 캐릭터마다 판정 띠를 따로 둔다(`HitShapes`에 캐릭터별 표, Shared·서버 변경 = 서버 세션 담당). 모양 차이를 살릴 수 있지만 캐릭터 고르기가 유불리 선택이 된다.

## 6. 확인한 것과 남은 일

확인한 것: 두 시트를 직접 열어 캐릭터 정체성, 8색·장식 구별, 어두운 배경 대비, 3면 일관성을 봤다. 판정 띠를 변형 줄 8명에 겹쳐 키·배·발·머리 폭을 쟀다(배 폭으로 축척을 맞춘 근사치, ±0.03유닛 정도).

확인 안 한 것: 흑백 변환·게임 크기 축소 확인(장식이 젤리와 같아 같은 결과로 봤음), 동작 시트(포즈 8종)는 아직 안 만듦, 색약 시뮬레이션.

남은 일(사용자 결정 대기):
- 시안 확정 여부와 판정 방법(위 1 또는 2).
- 확정되면: 동작 시트 콘셉트(선택) → Blender 모델(지금 스크립트에 몸 모양만 바꿔 넣는 구조) → 스프라이트 시트 → 캐릭터 고르기 기능(프로토콜 버전 올림, 서버·클라이언트 세션과 순서 맞춤).
