# 추가 캐릭터 (젤리곰·푸딩)

담당 세션: `[OnlineSeverGame] 캐릭터·맵 아트 · 02`
범위: 지금의 젤리 외에 고를 수 있는 캐릭터 후보를 추천하고, 사용자가 고른 젤리곰·푸딩의 콘셉트 시트를 만든 뒤(1~6장), 확정된 두 시안을 Blender 모델·스프라이트 시트로 만든다(8장). 게임에서 캐릭터를 고르는 기능(프로토콜 변경)과 Unity 연결은 다음 단계.

## 1. 어떻게 보이게 되는가

- **젤리곰**: 지금 젤리와 같은 반투명 젤리 재질의 통통한 곰. 머리·몸이 한 덩어리(목·허리 없음), 머리 위 둥근 귀 두 개, 배 옆에 붙은 짧은 팔, 눈 아래 밝은 곰 주둥이. 장식은 두 귀 사이.
- **푸딩**: 컵에서 뒤집어 꺼낸 커스터드 푸딩. 아래 2/3는 곧은 옆면, 위는 좁아져 평평한 윗면, 윗면을 덮고 흘러내린 붉은 호박색 캐러멜. 젤리보다 광택이 덜한 부드러운 재질. 장식은 캐러멜 위.
- 둘 다 몸 색 = 플레이어 색(1장 표의 8색), 머리 장식 8종도 지금과 같다. 같은 캐릭터를 여러 명이 골라도 색·장식으로 구별된다. 캐러멜 색은 8명 모두 같다.

## 2. 왜 이 둘인가 (추천 과정, 2026-11-10)

추가 캐릭터가 지켜야 할 조건:
1. **판정 모양이 같아야 한다.** 위험물은 그려진 몸 모양 띠에 맞는다(`Shared/Simulation/HitShapes.cs`의 `Body`: 배 폭 1.02, 발쪽 0.78, 머리 쪽 0.52까지 좁아짐, 키 1.2). 그림이 이 띠와 많이 다르면 캐릭터마다 판정이 달라 불공평하다. 머리 장식은 판정에서 빠지므로 귀·꼭지는 자유.
2. **몸 색 = 플레이어 색, 장식 8종 유지**(색약 대비가 그대로 산다).
3. **위험물과 헷갈리지 않아야 한다**: 칼·고드름·눈덩이·나무 상자·마카롱. 순백, 네모 상자, 마카롱 모양은 피한다.
4. **동작 8종·시트 규격 그대로**(Blender 스크립트와 Unity 코드를 다시 쓸 수 있게).

추천한 후보: 1 젤리곰, 2 푸딩, 3 마시멜로(어깨를 둥글게 깎아야 함), 4 찐빵·만두(색 반죽만, 흰 반죽 금지), 5 무늬 껍질 달걀(판정은 가장 정확하지만 지금 젤리와 너무 비슷). 넣지 않기로 한 것: 각설탕·두부(창고 상자와 혼동, 모서리가 판정 밖), 마카롱(디저트 맵 위험물), 눈사람·흰 찹쌀떡(흰색이 칼·눈덩이와 겹침), 아이스크림콘(아래가 좁음), 경단 꼬치(판정보다 좁음). 사용자가 젤리곰·푸딩 시안을 골랐다.

## 3. 어떻게 만들었는가

기준 프롬프트(개인 파일, `.vibe-local/prompts/`, Git 제외)는 규칙 2에 따라 기존 기준에서 필요한 것만 바꿨다.
- `style-gummybear_v1.md`, `style-pudding_v1.md`: style_v2의 STYLE·8색 장식 블록은 글자까지 같고, **CHARACTER BASE만** 캐릭터별로 새로 썼다. 몸 비율은 지금 게임 몸(폭 1.0 × 키 1.2)에 맞춰 "키 = 폭의 1.2배, 배가 가장 넓고 머리 쪽이 폭 절반"으로 썼다. 젤리곰은 "머리·몸 한 덩어리"(목에서 판정보다 좁아지지 않게), 귀는 몸 키 12% 이하, 팔은 몸 윤곽 밖으로 거의 안 나오게. 푸딩 캐러멜은 칼 손잡이(#4A2A1A)와 헷갈리지 않게 붉은 호박색(#B4532A).
- `character-sheet-gummybear_v1.md`, `character-sheet-pudding_v1.md`: character-sheet_v2 브리프 그대로, 바꿀 수 있는 입력인 "기본형 색"만 바꿈(우윳빛 반투명 / 연한 바닐라 + 캐러멜).
- 생성: `codex exec -m gpt-5.6-sol --skip-git-repo-check -C D:/OnlineSeverGame - < 프롬프트.txt`. Codex 설정의 기본 모델(`gpt-6.1-terra`)과 `gpt-6.1-sol`은 ChatGPT 계정에서 "지원 안 함" 오류가 나서 이번 실행에만 `-m gpt-5.6-sol`을 붙였다(설정 파일은 그대로). Codex CLI가 0.158.0으로 모델 목록(0.167.0 기준)보다 오래돼서일 수 있다.

## 8. Blender 모델과 스프라이트 (2026-11-10)

### 8.1 어떻게 보이는가

- **젤리곰**: 지금 젤리와 **똑같은 몸**(같은 회전체 단면, 같은 반투명 젤리 재질·8색·외곽선)에 머리 위 둥근 귀 두 개, 배 앞쪽에 붙은 짧은 팔, 눈 아래 밝은 주둥이 + 까만 코. 주둥이 색은 몸 색을 흰색 쪽으로 60% 섞은 색이라 8명마다 달라진다. 입은 주둥이 위에. 장식은 두 귀 사이 머리 꼭대기(왕관·체리처럼 큰 장식은 귀를 일부 가린다).
- **푸딩**: 둥근 바닥 → 곧은 옆면 → 어깨가 좁아지며 → 평평한 윗면(폭 약 0.48). 어깨 전체를 덮는 붉은 호박색 캐러멜(#B4532A, 8명 같음)이 몸 옆으로 둥근 방울 여섯 개로 흘러내린다. 흘러내림은 눈·입 자리를 피해 놓았다. 커스터드 몸은 광택 없이 툰 음영 + 테두리 빛만, 캐러멜에만 작은 광택.
- 동작 8종·표정·장식 움직임·시트 규격(256 프레임, 128 px/유닛, 피벗 = 몸 아래 가운데)은 젤리와 같다. 그래서 Unity 쪽은 시트 파일 이름만 바꾸면 같은 코드로 그릴 수 있다.

### 8.3 어떻게 만들었는가

같은 스크립트(`Art/blender/build_sprites.py`)에 캐릭터 종류(`jelly` / `bear` / `pudding`)를 넣었다. `set_kind()`가 몸 단면·눈·입 위치를 바꾸고, 래티스 셰이프 키·동작 표·장식·렌더·시트 합치기는 그대로 쓴다.

- **판정을 맞춘 방법**: 위험물 판정은 그려진 젤리 몸을 0.1유닛 띠마다 잰 표(`HitShapes.Body`, 반폭 0.39 / 0.47 / 0.51 / 0.46 / 0.41 / 0.36 / 0.26)다. 콘셉트에서는 두 캐릭터 모두 머리 쪽이 이 띠보다 약 0.1 넓었다(사용자 결정: Blender에서 좁히기).
  - 젤리곰은 몸 단면을 젤리와 **같은 함수**로 만들어 판정이 처음부터 같다. 콘셉트의 넓적한 머리는 포기하고 귀·주둥이·팔로 곰을 표현했다. 귀는 키 1.2 위(표 밖, 장식과 같은 자리)에 두고 화면에서 꼭대기 띠 반폭 0.26 안에 들어오게 했다. 팔은 몸 앞면에 붙여 실루엣 밖으로 안 나온다.
  - 푸딩은 단면을 띠 경계마다 맞춰 그렸다: 반폭 = 띠 반폭 − 외곽선 0.02. 어깨는 높이 0.8 / 0.9 / 1.0 / 1.1에서 반경 0.44 / 0.39 / 0.34 / 0.24를 지나는 직선 구간, 그 위는 둥근 모서리의 평평한 윗면, 바닥은 젤리처럼 둥글게. 그래서 띠마다 그림이 판정을 채우되 넘치지 않는다.
- **캐러멜**: 몸 메시 자체의 면에 재질만 다르게 칠했다(겉에 껍데기를 씌우면 그만큼 넓어져 판정과 어긋난다). 경계선이 계단처럼 보이지 않게 푸딩 몸만 메시를 촘촘하게(240 × 150) 했다.
- **장식 위치**: 몸 꼭대기의 가장 높은 점들의 평균에 장식을 올린다(푸딩은 윗면이 평평해서 한 점을 고르면 가장자리로 쏠렸다).
- **판정 측정 자동화**: `characters` 렌더 때 장식을 숨긴 몸만 대기 첫 프레임·대시 3프레임·밀려남 3프레임을 렌더해, 알파 0.5 이상 픽셀의 띠별 좌우 끝(피벗 기준 밀리유닛, 바깥쪽으로 10 단위 올림)을 `HitShapes.cs`에서 읽은 표와 비교한다. 표에는 젤리 그림 자체가 닿지 않는 여유 띠(대시 0.8~0.9, 밀려남 1.1 위)가 있어서, 새 캐릭터는 같은 방법으로 잰 **젤리 값과도** 비교한다.

### 8.5 확인한 것과 평가

실제 측정(`*_hitcheck.json`, 단위 밀리유닛 = 0.001유닛):

| 캐릭터 | 대기 몸(Body) vs 젤리 | 대시(Dash) vs 젤리 | 밀려남(Stunned) vs 젤리 |
|---|---|---|---|
| 젤리(기준) | 표와 최대 20 차이(반올림) | 표와 10, 0.8~0.9 띠는 젤리가 안 닿음(표의 여유) | 표와 60(1.1~1.2), 1.2 위 띠는 젤리가 안 닿음 |
| 젤리곰 | **0**(같은 몸) | 0.7~0.8 띠에서 뒤쪽 100 넓음 = 귀 | 1.0~1.2 띠에서 뒤쪽 60~140 넓음 = 귀 |
| 푸딩 | **10 이내** | 0.7~0.8 띠에서 뒤쪽 60 넓음 = 윗면 모서리 | 1.0~1.2 띠 뒤쪽 50~60 넓음(윗면 모서리), 0~0.1 띠 앞쪽 40 좁음(발) |

- "넓음"은 그림이 판정보다 크다는 뜻(칼이 그 부분을 스쳐 보여도 안 죽음 = 너그러운 쪽). 젤리곰의 차이는 모두 귀라서 장식과 같은 성격이다. 판정보다 그림이 **작은**(억울한) 곳은 푸딩 밀려남 중 발 0.04 하나뿐이다.
- 처음 푸딩 단면은 대기 몸 두 띠(발 0~0.1, 1.0~1.1)에서 그림이 0.03 좁았다. 어깨를 띠 경계를 지나는 직선 구간으로 바꾸고 바닥을 덜 둥글게 해서 젤리와 0.01 이내로 맞췄다.
- 프레임 잘림 없음(두 종류 × 8색 × 28프레임).
- 시트 2장(젤리곰 7번, 푸딩 2번) 전체와 비교 그림을 직접 열어 봤다: 8동작이 젤리와 같은 흐름으로 읽힌다. 귀(곰)·캐러멜(푸딩)로 종류가 한눈에 구별되고 8색·장식도 구별된다.

콘셉트와 달라진 점: 젤리곰은 콘셉트보다 머리가 좁고(판정 맞춤), 귀가 작다. 팔은 몸 옆 실루엣이 아니라 앞면의 작은 혹으로 보인다. 푸딩은 콘셉트보다 윗면이 좁고 어깨가 길어서 캐러멜이 어깨 전체를 덮는 "캐러멜 모자" 모양이 됐다.

확인 안 한 것: 게임 화면(Unity 연결 전), 맵 배경 위 대비, 흑백 구별(장식은 젤리와 같음), 크기를 줄였을 때 곰 귀가 읽히는지(비교 그림 축소로만 봄).
