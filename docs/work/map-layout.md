## 1. 무엇이 문제였고 무엇을 바꾸나

조율 세션이 확인한 문제: 네 맵 모두 **좌우 대칭, 발판 3~5개, 가장 높은 발판 4.8~6.0**이라 화면 위쪽 절반(6 ~ 13.5)이 비어 있고, 어느 맵이든 "바닥 → 낮은 발판 → 가운데 높은 발판"으로 같은 흐름이었다.

바꾸는 것:

| 맵 | 특징 구조 | 라운드 중간 이벤트 | 흐름 한 줄 |
|---|---|---|---|
| 주방 | **높은 탑**: 왼쪽 벽에 3단 양념 선반 탑(2.4 / 4.8 / 7.2) + 맨 위 국자 걸이(9.6) | **화구에 불**: 오른쪽 화구 두 개에 불이 붙어 그 바닥에 닿으면 탈락 | 오른쪽은 넓은 화구 바닥과 후드, 왼쪽은 위로 쌓인 탑. 불이 붙으면 화구 위 사람들이 쟁반 선반·탑으로 몰린다 |
| 겨울 처마 | **사라졌다 나타나는 발판**: 눈 차양 두 개가 번갈아 무너졌다 다시 생김 | **강풍**: 모두 한쪽으로 밀림(엎드리면 절반) | 왼쪽·오른쪽 두 갈래 계단이 맨 위 돌 선반(9.6)에서 만난다. 차양이 무너질 때마다 한쪽 길이 끊긴다 |
| 창고 | **움직이는 발판**: 크레인에 매단 팔레트(8.4)가 좌우로 왕복 | **컨베이어 벨트**: 가운데 바닥이 한 방향으로 움직임 | 왼쪽은 낮은 작업대 → 벽 선반 → 통로 계단, 오른쪽은 3단 랙. 위에서는 팔레트를 타고 건너간다 |
| 디저트 가게 | **위아래로 움직이는 케이크 리프트**(1.2 ↔ 7.2) | **시럽 바닥**: 바닥 절반이 끈적해져 걷기 절반 | 왼쪽은 녹는 아이스크림 계단(2.4 → 4.8 → 7.2 → 체리 9.6), 오른쪽은 리프트를 타고 웨하스(7.2)로 |

공통 원칙:
- **비대칭**: 네 맵 모두 왼쪽과 오른쪽 구조가 다르다. 스폰 지점도 그 구조에 맞게 고르게 퍼진다.
- **높낮이**: 발판 높이는 1.2 / 2.4 / 3.6 / 4.8 / 6.0 / 7.2 / 8.4 / 9.6 중에서 쓴다. 한 단 차이는 2.4 이하(점프 최고 2.8로 오름), 위로 갈수록 좁아진다.
- **위쪽 공간**: 네 맵 모두 7.2 이상 발판이 있고 맨 위는 8.4 ~ 9.6(머리 10.8, 점프 꼭대기 12.4). 위험물 시작 높이 14.0(겨울 11.8)은 그대로라 예고 시간은 같다.
- **지붕 있는 면**(위에서 떨어지는 위험물이 먼저 멈추는 면이 위에 있는 곳)은 옆 위험물 레인(`SideKnifeSurfaces`)이 반드시 겨눈다(3장 검증).

## 2. 맵별 배치 (단계 B 기준 수치)

표기: `(왼쪽 x ~ 오른쪽 x, 윗면 y)`. 모든 발판은 기존처럼 한 방향(위에서만 착지, 아래에서 통과, ↓+점프로 내려가기). 스폰 지점은 모두 바닥(y = 0), 참가 순서대로 쓴다. R = 오른쪽을 봄, L = 왼쪽.

### 2.1 주방 (id 1) — 높은 탑 + 화구

밤의 거대한 주방. 왼쪽 벽에 양념 선반 탑, 가운데 벽걸이 도마, 오른쪽은 가스레인지 화구 네 개와 그 위 레인지 후드.

```
  9.6        [국자 걸이]
  7.2 [선반3]                                   [=====후드=====]
  4.8 [선반2]                  [===도마===]
  2.4 [선반1]                           [쟁반 선반]
  0.0 ==============================(화구1)(화구2)(화구3)(화구4)=  도마 바닥 + 가스레인지
      0 1     4 5      9 9.5      12.5 13.5 15.5 16  20.5  24
                              화구: 10~13 / 13.5~16.5 / 17~20 / 20.5~23.5
```

| 면 | 종류 | x 범위 | 윗면 y | 밀리유닛 |
|---|---|---|---|---|
| 바닥 | 도마 + 가스레인지(오른쪽) | 0 ~ 24 | 0 | |
| 양념 선반 1 | 탑 | 1.0 ~ 4.0 | 2.4 | 1000 ~ 4000, 2400 |
| 양념 선반 2 | 탑 | 1.0 ~ 4.0 | 4.8 | 1000 ~ 4000, 4800 |
| 양념 선반 3 (탑 꼭대기) | 탑 | 1.0 ~ 4.0 | 7.2 | 1000 ~ 4000, 7200 |
| 국자 걸이 | 벽걸이 막대 | 5.0 ~ 9.0 | 9.6 | 5000 ~ 9000, 9600 |
| 벽걸이 도마 | 나무 | 9.5 ~ 13.5 | 4.8 | 9500 ~ 13500, 4800 |
| 쟁반 선반 | 쇠 | 12.5 ~ 15.5 | 2.4 | 12500 ~ 15500, 2400 |
| 레인지 후드 | 쇠 | 16.0 ~ 20.5 | 7.2 | 16000 ~ 20500, 7200 |

- 오르는 길: 바닥 → 선반 1 → 2 → 3(같은 x라 제자리 점프로 아래에서 통과해 올라섬) → 국자 걸이(오른쪽으로 1.0 틈, 2.4 위). 바닥 → 쟁반 선반 → 도마(x 12.5~13.5 겹침) → 후드(오른쪽으로 2.5 틈을 달리며 점프, 11틱째 착지 지점 x 17.4~18.3).
- 밀리는 버터 블록 1개: 바닥 x **7.0** (6.4 ~ 7.6, 1.2 × 1.0), 국자 걸이 아래.
- 스폰: x = 2.5 R, 22.0 L, 11.0 R, 18.5 L, 5.5 R, 14.5 L, 8.5 R, 20.5 L.
- 흔들리는 장식: 마늘(선반 2 아랫면에 매달림, 2.5, 4.75), 수건(국자 걸이, 6.0, 9.55), 국자(국자 걸이, 8.0, 9.55), 허브(바닥에 섬, 4.5, 0).
- 지붕 있는 면: 바닥(탑·국자 걸이·도마·쟁반·후드 아래), 선반 1(선반 2·3 아래), 선반 2(선반 3 아래). → **옆 레인 면 `0, 2.4, 4.8`**. 쟁반 선반은 도마와 1.0만 겹쳐 몸이 다 가려지지 않는다(3.2 판정).
- 이벤트: 화구에 불(4.1).

### 2.2 겨울 처마 (id 2) — 사라지는 눈 차양 + 강풍

눈 덮인 집 벽. 처마(13.0)에 고드름 24자리는 그대로. 왼쪽은 얼음 창턱 → 나무 들보 → 눈 차양, 오른쪽은 얼음 창턱 → 눈 차양 → 얼어붙은 홈통, 두 길이 가운데 위 돌 선반에서 만난다.

```
 13.0 ▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼▼  처마(고드름)
  9.6                               [=돌 선반=]
  7.2                    [*차양1*]                 [~~~얼음 홈통~~~]
  4.8          [==들보==]                   [*차양2*]
  2.4 [~얼음 창턱L~]                 [~얼음 창턱R~]
  0.0 ===========[~~~~~얼음 웅덩이~~~~~]=====================  눈 바닥
      0 1      5 6.5   10.5 11  14 14.5 15  18 18.5 19  21.5 23.5 24
```

| 면 | 종류 | x 범위 | 윗면 y | 밀리유닛 |
|---|---|---|---|---|
| 바닥 | 눈 | 0 ~ 24 | 0 | |
| 바닥 얼음 웅덩이 | **얼음** | 6.5 ~ 14.0 | 0 | 6500 ~ 14000 |
| 왼쪽 창턱 | **얼음** | 1.0 ~ 5.0 | 2.4 | 1000 ~ 5000, 2400 |
| 들보 | 나무 | 6.5 ~ 10.5 | 4.8 | 6500 ~ 10500, 4800 |
| 눈 차양 1 | 나무 + 눈, **사라짐** | 11.0 ~ 14.0 | 7.2 | 11000 ~ 14000, 7200 |
| 돌 선반 | 돌 | 15.0 ~ 18.0 | 9.6 | 15000 ~ 18000, 9600 |
| 오른쪽 창턱 | **얼음** | 14.5 ~ 18.5 | 2.4 | 14500 ~ 18500, 2400 |
| 눈 차양 2 | 나무 + 눈, **사라짐** | 18.5 ~ 21.5 | 4.8 | 18500 ~ 21500, 4800 |
| 얼음 홈통 | **얼음** | 19.0 ~ 23.5 | 7.2 | 19000 ~ 23500, 7200 |

- 오르는 길(왼쪽): 바닥 → 왼쪽 창턱 → 들보(1.5 틈) → 차양 1(0.5 틈) → 돌 선반(1.0 틈). (오른쪽): 바닥 → 오른쪽 창턱 → 차양 2(맞닿음) → 홈통(겹침, 제자리 점프) → 돌 선반(왼쪽으로 1.0 틈).
- **사라지는 눈 차양**(특징 구조): 라운드 시작부터 있다가, 무너지기 2초(40틱) 전부터 흔들리며 눈이 떨어지고(예고, 그동안 발판), 4초(80틱) 동안 사라졌다가 다시 쌓인다. 주기 12초(240틱).
  - 차양 1: 처음 무너짐 roundTick **200**(10초) → 200~280, 440~520, 680~760 … 없음.
  - 차양 2: 처음 무너짐 roundTick **320**(16초) → 320~400, 560~640 … 없음.
  - 두 차양이 동시에 없는 순간은 없다 → 돌 선반으로 가는 길은 늘 하나 이상 열려 있다. 위에 서 있다 사라지면 그냥 떨어진다(아래는 바닥·창턱).
  - 이유: 같은 맵에서 "어느 쪽으로 올라갈지"가 판마다·시간마다 바뀐다. 4초는 다시 생길 때까지 기다릴 만큼 짧고, 그동안 한쪽 길로 사람이 몰릴 만큼 길다.
- 고드름 규칙 그대로: 얼음 면(창턱 2개·홈통)은 뚫고, 나무·돌·눈 차양에서 부서진다. 그래서 **얼음 창턱·홈통 아래는 지붕이 아니다.**
- 밀리는 눈덩이 1개: 바닥 x **3.0** (2.5 ~ 3.5, 1.0 × 1.0, 왼쪽 창턱 아래).
- 스폰: x = 1.5 R, 22.5 L, 9.0 R, 16.5 L, 5.5 R, 19.5 L, 12.0 R, 14.0 L.
- 흔들리는 장식: 등불 2개(처마 아래 3.0, 13.0 / 21.0, 13.0, 그대로).
- 지붕 있는 면: 바닥(들보·차양·돌 선반 아래), 오른쪽 창턱(돌 선반 아래, 고드름은 창턱을 뚫어도 돌 선반에서 멈춤). → **옆 레인 면 `0, 2.4`**(지금과 같음).
- 이벤트: 강풍(4.2).

### 2.3 창고 (id 3) — 움직이는 크레인 팔레트 + 컨베이어

어두운 창고. 왼쪽 벽은 낮은 작업대·벽 선반·통로(계단식), 오른쪽 벽은 3단 철제 랙. 천장 크레인 레일(13.2~13.6)에 매단 팔레트가 가운데 위를 좌우로 오간다. 가운데 바닥에는 컨베이어 벨트가 깔려 있다.

```
 13.4 ===================== 크레인 레일 =====================
  8.4               [팔레트] ⇄⇄⇄⇄⇄⇄⇄⇄⇄⇄ [팔레트]         (6.5~10.5 ↔ 13.5~17.5)
  7.2                                              [랙 3칸]
  6.0     [통로]                                    
  4.8                                              [랙 2칸]
  3.6 [벽선반]                                      
  2.4                                              [랙 1칸]
  1.2 [=====작업대=====]                            
  0.0 ======[≡≡≡≡≡≡≡≡≡≡≡ 컨베이어 6.0~19.0 ≡≡≡≡≡≡≡≡≡≡]=====  콘크리트 바닥
      0 0.5 2.5 3.5 6       10.5 13.5        17.5 19   23.5 24
```

| 면 | 종류 | x 범위 | 윗면 y | 밀리유닛 |
|---|---|---|---|---|
| 바닥 | 콘크리트(가운데 컨베이어) | 0 ~ 24 | 0 | 컨베이어 6000 ~ 19000 |
| 작업대 | 쇠 다리 탁자 | 0.0 ~ 6.0 | 1.2 | 0 ~ 6000, 1200 |
| 벽 선반 | 철판 | 0.5 ~ 3.5 | 3.6 | 500 ~ 3500, 3600 |
| 통로 | 철망 | 2.5 ~ 6.0 | 6.0 | 2500 ~ 6000, 6000 |
| 크레인 팔레트 | 나무, **움직임** | 6.5 ~ 10.5 ↔ 13.5 ~ 17.5 | 8.4 | 폭 4000, 왼쪽 끝 6500 ↔ 13500 |
| 랙 1칸 | 철판 | 19.0 ~ 23.5 | 2.4 | 19000 ~ 23500, 2400 |
| 랙 2칸 | 철판 | 19.0 ~ 23.5 | 4.8 | 19000 ~ 23500, 4800 |
| 랙 3칸 | 철판 | 19.0 ~ 23.5 | 7.2 | 19000 ~ 23500, 7200 |

- **크레인 팔레트**(특징 구조): 왼쪽 끝(6.5~10.5)에서 2초(40틱) 멈췄다가 오른쪽으로 7.0유닛을 100틱(5초, 70/틱 = 1.4 u/s)에 가고, 오른쪽 끝(13.5~17.5)에서 2초 멈췄다가 돌아온다. 주기 14초(280틱). roundTick 0(카운트다운·대기·결과)에는 왼쪽 끝에 멈춰 있다.
  - 위에 선 플레이어와 상자는 팔레트가 움직인 만큼 같이 옮겨진다(5.1). 팔레트 끝에서 걸어 나가면 떨어진다.
  - 이유: 왼쪽 통로(6.0)와 오른쪽 랙 꼭대기(7.2)를 잇는 유일한 다리라서, 위층 사람들이 "팔레트가 올 때까지 기다리기 / 건너가기"를 선택한다. 1.4 u/s는 걸어서 쉽게 따라잡을 만큼 느리고, 아래 바닥에는 움직이는 지붕이 된다.
- 오르는 길(왼쪽): 바닥 → 작업대(1.2) → 벽 선반(3.6) → 통로(6.0, x 2.5~3.5 겹침) → 팔레트(왼쪽 끝에 있을 때 0.5 틈, 2.4 위). (오른쪽): 바닥 → 랙 1 → 2 → 3(제자리 점프) → 팔레트(오른쪽 끝에 있을 때 1.5 틈, 1.2 위).
- 떨어진 화물 상자는 지금처럼 밀리는 상자가 된다(작업대·랙·통로·팔레트 위에도). 팔레트 위 상자는 팔레트와 함께 움직인다.
- 시작 상자 2개: 바닥 x **9.0**, **15.0** (8.3~9.7, 14.3~15.7, 1.4 × 1.2, 둘 다 컨베이어 위).
- 스폰: x = 3.0 R, 21.0 L, 11.0 R, 13.0 L, 5.0 R, 17.5 L, 7.0 R, 19.5 L.
- 흔들리는 장식: 크레인 갈고리 2개(레일, 3.0, 13.2 / 21.0, 13.2).

### 2.4 디저트 가게 (id 4) — 케이크 리프트 + 시럽

## 3. 수치 검증 (단계 B 테스트가 코드로 확인)

모두 `Server/GameServer.Tests/MapLayoutTests.cs`에서 실제 물리·판정 코드로 계산한다(사람이 손으로 잰 값이 아니다). 움직이는/사라지는/녹는 발판이 있으므로 **roundTick 0 ~ 3600을 10틱 간격으로** 모든 시각에서 확인한다.

### 3.1 8명이 설 자리
- 바닥만 24유닛 = 그린 몸 폭 1.02 기준 23명분. 이벤트로 바닥 일부가 위험해도(주방 불 6.0유닛, 4.1) 18유닛 = 17명분.
- 확인: 모든 시각에 (바닥 + 있는 발판 폭 − 불 붙은 화구 폭) ÷ 1.02 ≥ 8. 스폰 8자리가 모두 바닥 위, 서로·상자와 겹치지 않음.

### 3.2 숨으면 안전한 곳이 없는가
"안전한 자리" = 그 자리에 가만히 서 있거나 엎드려 있으면 **위에서 떨어지는 위험물도, 옆 위험물 레인도 몸에 닿지 않는 곳**. 하나도 없어야 한다.
- 모든 시각, 모든 면(바닥·발판·처음 놓인 상자 윗면, 창고는 1단·2단 상자 높이 1.2·2.4 추가)의 x를 0.1 간격으로, 자세 두 가지(서기·엎드리기)마다:
  - 낙하: 그 맵 위험물을 위험물 x 0.05 간격으로 시작 높이에서 떨어뜨려(`KnifePhysics.Step`, 그 시각 지형) 그린 모양(`HitShapes`)이 몸에 닿는 x가 하나라도 있으면 "위에서 위험".
  - 옆: 그 맵 레인(`SideKnifePhysics.Lanes`) 중 하나라도 그 자세의 몸을 지나면 "옆에서 위험".
  - 둘 다 아니면 실패(그 자리·자세·시각을 메시지로).
- 위 2장의 "지붕 있는 면"과 레인 면 목록은 이 계산을 통과하도록 정한 것이다. 단계 B에서 실패하면 레인 면을 더하거나 발판 폭을 줄이고 이 문서를 고친다.
- **단계 B에서 이 검사가 찾아 고친 것**(처음 설계의 숨는 자리 두 곳):
  1. 디저트: 바닐라(5.5~11.5) 위로 초코(처음 10.5~13.5)가 1.0 겹쳤다. 몸은 발판 끝 밖 0.4까지 설 수 있어서(그린 몸 폭 1.02) 바닐라 오른쪽 끝(x 11.0~11.9)에 서면 몸 전체가 초코 아래에 들어가 포크가 닿지 않았고, 4.8에는 옆 레인이 없다. → 초코를 바닐라가 끝나는 x 11.5부터(11.5~14.5), 체리·리프트·웨하스·민트도 같은 규칙으로 1.0씩 오른쪽으로.
  2. 겨울: 고드름은 x = 0.5 + 정수 자리에서만 떨어진다. 돌 선반(처음 14.5~18.0)이 차양 1(11~14) 끝 바로 옆에 있어 차양 1 오른쪽 끝(x 14.25)이 "왼쪽 자리 13.5의 고드름은 차양에 걸리고 14.5의 고드름은 돌 선반에 걸리는" 틈이 됐다. 오른쪽 끝을 18.5로 늘린 시안은 차양 2·홈통 왼쪽 끝에 같은 틈을 만들었다. → 돌 선반 15.0~18.0.
  - 규칙: **위층 발판은 아래층 발판의 설 수 있는 범위(가장자리 밖 0.4까지) 위로 걸치지 않게, 아래층이 끝나는 x에서 시작한다.** 걸쳐야 하면(탑, 랙) 그 아래층 높이를 옆 레인 면에 넣는다. 오르기는 맞닿음·1.5 이하 틈으로 충분하다.

### 3.3 위·옆 위험물을 모두 피할 수 있는 동선
- **옆 위험물**: 모든 면(움직이는 리프트는 1.2~7.2를 0.1 간격, 팔레트는 8.4)에서 모든 레인·양방향이 "안 닿음 / 엎드려 피함 / 점프로 넘음" 중 하나(기존 `Every_lane_can_be_survived_from_every_surface_of_its_map`을 새 면 목록으로).
- **위에서 떨어지는 위험물**: 예고 20~25틱(1~1.25초) 동안 걸어서 8~10유닛을 간다. 위험물이 몸을 맞힐 수 있는 폭은 1.4(식칼)~2.4(화물 상자)라 바닥과 폭 2.4 이상 발판에서는 옆으로 비켜서 피할 수 있다. 더 좁은 곳(녹은 초코 1.0, 탑 선반 3.0 중 일부)은 내려가거나 옆 발판으로 옮겨야 한다.
- **오르내리는 길**(동선): 바닥에서 출발해 실제 `PlayerPhysics.Step`으로 "서기/걷기 방향 × 점프 시점 × 공중에서 방향키를 떼는 틱 × 대시" 조합을 돌려 닿는 면을 그래프로 만들고, **모든 발판에 바닥에서 갈 수 있고 모든 발판에서 바닥으로 돌아올 수 있음**을 확인한다. 움직이는/사라지는 발판은 그 발판이 닿는 시각(팔레트 양 끝, 리프트 위·아래, 차양이 있을 때)에 확인한다. 녹는 발판은 처음과 최소 폭 두 시각.
- 이벤트 중 동선: 주방 불이 붙은 동안에도 불 없는 바닥이 이어져 있고(불 붙는 화구는 한 번에 두 개, 사이가 3.5 이상 떨어짐) 쟁반 선반(2.4)·탑으로 올라갈 수 있다. 강풍·컨베이어 중에도 걸으면 거슬러 갈 수 있다(바람 120, 벨트 150 < 걷기 400).

## 4. 라운드 중간 맵 이벤트

### 4.0 공통 규칙
- 맵마다 하나. **roundTick만으로 정해진다**(무작위 없음): 서버·클라이언트 예측·봇이 같은 함수(`MapEventPhysics.At(stage, roundTick)`)로 같은 상태를 얻는다. 그래서 **패킷에 이벤트 상태를 싣지 않는다**(스냅샷의 roundTick으로 충분, 녹는 발판과 같은 방식).
- 시간표: 첫 이벤트 **30초**(예고는 28초부터), 그 뒤 **40초마다**(70, 110, 150초). 예고 **2초(40틱)**, 지속은 맵별(아래). n번째 이벤트(0부터)는 n이 짝수/홀수에 따라 방향이나 자리가 바뀐다.
  - 이유: 옆 위험물이 20초에 시작하므로 그것에 익숙해진 뒤 새 요소가 들어오게 30초. 피하는 봇 판 길이가 50~110초라 한 판에 이벤트가 1~2번 나온다. 40초 간격이면 이벤트 사이 28~32초가 평소 상태라 "평소 흐름 → 이벤트로 판이 흔들림"이 반복된다.
- Playing에만 생긴다(Countdown·Ended·Waiting은 roundTick 0 → 없음).
- 예고 2초 동안은 무해하고 화면에 표시만 한다(4.5).

| 맵 | 이벤트 | 예고 | 지속 | 세기 | n 짝수 / 홀수 |
|---|---|---|---|---|---|
| 주방 | 화구에 불 | 40틱 | **160틱(8초)** | 불꽃 높이 0.8, 닿으면 탈락 | 화구 1·3 / 화구 2·4 |
| 겨울 처마 | 강풍 | 40틱 | **200틱(10초)** | 틱당 x ± 120 (2.4 u/s), 엎드리면 60 | 오른쪽으로 / 왼쪽으로 |
| 창고 | 컨베이어 벨트 | 40틱 | **240틱(12초)** | 틱당 x ± 150 (3 u/s) | 오른쪽으로 / 왼쪽으로 |
| 디저트 가게 | 시럽 바닥 | 40틱 | **240틱(12초)** | 걷기·엎드려 걷기 속도 절반 | 왼쪽 절반 / 오른쪽 절반 |

### 4.1 주방: 화구에 불
- 화구 네 개(바닥 x 10.0~13.0, 13.5~16.5, 17.0~20.0, 20.5~23.5). n 짝수면 1·3번, 홀수면 2·4번에 불이 붙는다.
- 불꽃 = 화구 x 범위 × 높이 0~0.8. 살아 있는 플레이어의 **그린 몸 모양**(`HitShapes.OfPlayer`, 지금 자세)이 불꽃 사각형과 겹치면 탈락. 결과 cause **4 = 맵 이벤트**(새 값). 같은 틱의 낙하물·옆 위험물 탈락과 함께 동시 사망 규칙(공동 승리)에 들어간다.
- 피하기: 불 없는 화구·바닥으로 걸어가거나(예고 2초 동안 16유닛), 쟁반 선반(2.4, 화구 위)·탑으로 올라가거나, 점프로 넘는다(발이 0.8 위에 있는 시간 12틱 = 4.8유닛 → 폭 3.0 화구를 달려 넘을 수 있음). 엎드리기는 소용없다.
- 세기 이유: 탈락은 무겁지만 예고 2초 + 불 자리가 늘 같은 네 칸 중 두 칸이라 읽을 수 있다. 8초는 "화구 위 지붕 아래(후드·도마·쟁반 아래 바닥)에 숨던 사람들"을 밖으로 몰아내기에 충분하고 판을 끝내 버리지는 않을 길이다. 이 맵의 바닥은 지붕이 많아(2.1) 숨기 쉬운데, 불이 그 숨는 자리를 주기적으로 없앤다.
- 화구 위 플레이어 처리: 불은 바닥에만 있다. 쟁반 선반 위·점프 중에는 안전. 밀리는 버터 블록은 불의 영향이 없다(화구에서 멀다).

### 4.2 겨울 처마: 강풍
- n 짝수면 오른쪽으로(+), 홀수면 왼쪽으로(−) 분다. 살아 있는 모든 플레이어의 x에 매 틱 `± 120`을 더한다(걷기·대시·밀려남·공중 모두. 벽에서 멈춤). **땅 위에서 엎드리면 `± 60`.**
- 바람을 거슬러 걸으면 초당 5.6유닛, 바람 따라 10.4유닛. 가만히 서 있으면 10초에 24유닛(벽까지) 밀린다.
- 얼음 위도 같다(속도가 아니라 위치에 더하므로 미끄러짐과 따로). 밀리는 눈덩이·위험물은 바람을 받지 않는다(판정과 예측을 단순하게).
- 이유: 좁은 발판(차양 3.0, 돌 선반 3.5)에서 버티려면 계속 거슬러 걷거나 엎드려야 하고, 고드름 자리(정해진 24자리)를 피해 서 있던 위치가 밀려난다. 걷기의 30%라 억울하게 떨어지지는 않을 세기.

### 4.3 창고: 컨베이어 벨트
- 바닥 x 6.0~19.0이 벨트. n 짝수면 오른쪽(+), 홀수면 왼쪽(−)으로 틱당 150 움직인다.
- 틱 시작에 바닥(y = 0)에 서 있고 몸 가운데가 벨트 위인 플레이어는 x에 ±150이 더해진다(그다음 벽·상자 옆면 막힘은 평소대로). 공중이면 영향 없음.
- 바닥에 놓인 밀리는 상자(시작 상자·떨어진 화물 상자)도 가운데가 벨트 위면 같이 움직인다 → 벨트 끝(작업대 아래·랙 아래)에 상자가 쌓이고, 상자가 앞의 플레이어를 밀어낸다(기존 상자 규칙).
- 이유: 상자가 쌓이며 지형이 바뀌는 창고 규칙을 이벤트가 한 번에 크게 흔든다. 3 u/s는 걸어서 거슬러 갈 수 있는 속도(초당 5유닛)이고, 12초면 바닥 상자가 벨트 끝으로 다 모인다(13유닛 / 3 = 4.3초).

### 4.4 디저트 가게: 시럽 바닥
- n 짝수면 바닥 x 0.5~11.5, 홀수면 12.5~23.5에 시럽이 깔린다.
- 틱 시작에 바닥(y = 0)에 서 있고 몸 가운데가 시럽 위인 플레이어는 걷기 목표 속도가 절반(200, 엎드려 80)이다. 점프·대시는 그대로(대시가 시럽에서 빠져나오는 수단).
- 이유: 지붕 있는 바닥(아이스크림·리프트·웨하스 아래)에 숨던 사람이 포크를 옆으로 비켜 피하기 어려워진다(예고 1초에 4유닛). 바닥 절반만 덮어 반대쪽으로 피할 곳이 있다.

### 4.5 화면 (클라이언트, 그림은 맵 비주얼 세션)
- 예고 2초: 해당 자리(화구·벨트·시럽 자리, 바람은 화면 전체)가 깜빡이고, 화면 위쪽 가운데에 이벤트 이름과 방향(예: "강풍 →")이 나온다. 깜빡임은 낙하 예고 기둥과 같은 박자.
- 지속 중: 불꽃(화구 폭 × 0.8 + 일렁임), 바람 줄무늬(방향으로 흐름, 눈발), 벨트 무늬가 방향으로 흐름, 시럽 웅덩이(갈색 반투명). 끝나기 1초 전부터 옅어진다.
- 그림이 오기 전에는 단색 도형으로 그린다(6장 목록의 크기·위치 그대로).

## 5. 어떻게 구현했는가 (단계 B)

핵심 결정: **움직이는 발판·사라지는 발판·맵 이벤트를 모두 roundTick의 정수 함수로 만들었다.** 기존 녹는 아이스크림(`Stage.AtRoundTick`)과 같은 방식이라, 서버·클라이언트 예측·봇이 같은 틱에 같은 지형과 이벤트를 얻고 패킷에 아무것도 더 싣지 않는다. 무작위를 넣지 않은 이유도 이것이다(넣으면 시작 정보를 패킷으로 보내야 한다). 대신 n번째 이벤트마다 방향·자리를 번갈아 바꿔 단조롭지 않게 했다.

### 5.1 공용 (`Shared/Simulation/`)
- `PlatformMotion.cs`(새 파일): `Shuttle(dx, dy, travel, pause)`(왕복, 끝마다 멈춤, 위치 = `shift × 진행 / travel` 정수 계산), `Blink(firstGone, period, gone, warning)`(사라졌다 나타남, 직전 warning틱은 Crumbling).
- `Platform`: `Motion`, 그 틱 상태 `Dx, Dy`(직전 틱에서 움직인 양), `Gone`, `Crumbling` 추가. `Platform.WithMotion(l, r, top, motion)`. `Platform.AtRoundTick(t)` = 녹기 + 움직임 + 사라짐.
- `Stage`: 생성자 인자 `mapEvent`(`MapEventSpec`), 필드 `EventSpec`, `RoundTick`, `Event`. `AtRoundTick(t)`는 녹기·움직임·사라짐·이벤트를 담은 **읽기 전용 복사본**(기존처럼 같은 틱 하나만 캐시, 복사본은 스폰·상자·장식 목록을 원본과 공유해 매 틱 배열 복사를 하지 않음). roundTick 0은 정의된 맵 그대로. 착지·발판·얼음 판정은 `Gone` 발판을 건너뛴다.
- **태워 옮기기**: `PlayerPhysics.CarryOnPlatform` — `Step` 맨 앞에서 땅에 서 있고 직전 틱 그 발판 윗면(`Top − Dy`)·x 범위(`− Dx`)에 서 있었으면 `X += Dx`(벽 안), `Y += Dy`. 위로 가는 리프트에서도 이걸 먼저 해야 착지 검사(이전 y ≥ 윗면)가 성립해 발판을 뚫고 떨어지지 않는다. `PushablePhysics.Step`도 상자에 같은 규칙(그래서 팔레트에 떨어진 화물 상자가 같이 다님).
- `MapEvent.cs`(새 파일): `MapEventKind`(1 불, 2 강풍, 3 컨베이어, 4 시럽), `MapEventSpec`(첫 틱, 주기, 예고, 지속, 세기, 자리 묶음), `MapEventState`(Phase, Index, Dir, TicksLeft, Spans), `MapEventPhysics.At / PlayerPush / BoxPush / WalkPercent / FireSeparation`.
  - 강풍·벨트는 `PlayerPhysics.Step`이 틱 시작에 값을 정해 `X += Vx + 이벤트 이동`(속도와 따로 위치에 더함 → 얼음 미끄러짐·넉백과 섞이지 않음). 시럽은 걷기 목표 속도 × 50%. 모두 예측에 그대로 들어간다.
  - 불은 판정이라 서버만: `HitShapes.RectSeparation`(새 함수, 그린 몸 띠 vs 고정 사각형).
- `HitShapes.RectSeparation`, `EliminationCause.MapEvent = 4`, `ProtocolConstants.Version = 7`.

### 5.2 서버 (`Server/GameServer/GameRoom.cs`)
- `StepMapEvent`: 옆 위험물 다음, 종료 검사 전. 불 판정·탈락(cause 4)과 단계가 바뀔 때마다 로그(`event fire#1 warning at roundTick 560 on map 1 'Kitchen' (burners 10~13 17~20)` / `on` / `off`). 사망 줄 `by fire`, 라운드 끝 줄 `events: 1 fire, event kills: 1`.
