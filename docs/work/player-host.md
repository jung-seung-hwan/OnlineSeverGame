# 작업 기록: 플레이어가 방장 (방 만들기 · 주소로 참가)

> 2026-11-11 시작. 브랜치 `claude/store-release-915848`(스토어 출시 준비와 같은 브랜치). 프로토콜 **v13**.

## 1. 어떻게 노나

- 접속 화면에 버튼이 둘이다.
  - **방 만들기**: 이 PC가 방장이 된다. 게임 안에서 서버가 켜지고, 방장은 바로 대기 화면에 들어간다.
  - **참가**: 아래 '주소' 칸에 방장이 알려 준 주소(예: `123.45.67.89:7777`)를 넣고 누른다. 마지막으로 넣은 주소는 기억한다.
  - 예전의 공개 서버 주소(`wildmagic.co.kr:7771`)는 기본값에서 뺐다. 그 서버는 시험용이었다. 예전 기본값이 저장돼 있으면 처음 켤 때 지운다.
- 방장의 대기 화면 위 가운데에 **친구가 접속할 주소** 칸이 있다.
  - 인터넷 주소(공인 IP:포트): 공유기의 UPnP로 포트를 자동으로 열어 본다. 결과는 "여는 중… / 자동으로 열었습니다 / 열지 못했습니다(포트포워딩 안내)" 중 하나로 보인다.
  - 같은 공유기 주소(내부 IP:포트): 같은 집·같은 와이파이 친구는 이 주소로 바로 들어온다.
  - **주소 복사** 버튼: 인터넷 주소가 있으면 그것을, 없으면 같은 공유기 주소를 클립보드에 넣는다.
  - 공유기가 두 단계(공인 IP가 사설 대역)라 밖에서 못 들어오면 그렇게 알려 준다.
- **시작** 버튼은 방장에게만 보인다. 혼자여도 누를 수 있다. 다른 사람은 "방장이 시작하기를 기다리는 중"을 본다.
  - 한 번 시작하면 그다음 판은 예전처럼 결과 화면 뒤에 저절로 이어진다.
  - 인원이 모자라 대기로 돌아가면 다시 방장이 눌러야 한다.
- 방장이 나가거나 게임을 닫으면 방이 닫힌다. 다른 사람은 "방이 닫혔습니다(방장이 나갔을 수 있어요)"와 함께 접속 화면으로 돌아간다.
- 맵 고르기, 캐릭터, 이모트, 판정은 예전과 같다. 방장은 지금처럼 가장 먼저 들어온 사람이고, 방을 만든 사람이 항상 첫 번째다.

## 2. 어떻게 만들었나

### 서버를 게임 안으로
- 서버 본체(`GameServer`·`GameRoom`·`Connection`·`InputBacklog`·`HitStats`·`LockedQueue`·`Log`·`TickTimer`)를 `Server/GameServer/`에서 **`Shared/Server/`**로 옮겼다(`git mv`, 내용은 그대로).
  - Unity가 쓰는 `Shared` 규칙에 맞게 C# 9로 바꿨다: 블록 namespace와 명시적 using, `record struct` 두 개(`NetEvent`, `Outgoing`)는 보통 `readonly struct`, `OperatingSystem.IsWindows()`는 `RuntimeInformation.IsOSPlatform`.
  - 바꾼 이유: 서버를 따로 실행 파일로 넣으면 패키지가 커지고, 게임이 비정상 종료될 때 서버가 남는다. 같은 프로세스면 실행 파일이 하나이고 방장이 나가면 서버도 같이 닫힌다. 콘솔 서버·테스트·봇은 같은 코드를 그대로 쓴다.
  - `Server/GameServer/`에는 `Program.cs`(명령줄 옵션)만 남았다. 테스트는 `InternalsVisibleTo`(`Shared/Server/AssemblyInfo.cs`)로 예전처럼 내부 멤버를 본다.
- `Log.Sink`: 콘솔 서버는 표준 출력, 게임은 Unity 로그(Player.log)에 `[Host]`를 붙여 적는다.
- `ServerOptions.LogAddresses`: 게임 안 서버는 **접속한 사람의 IP를 로그에 적지 않는다**(콘솔 서버는 예전처럼 적는다).
- 게임 루프 스레드를 백그라운드 스레드로 바꿨다. 게임 쪽에서 `StopAndWait`로 닫지 못해도 프로세스 종료를 막지 않는다.
- 클라이언트 `Client/Assets/Scripts/Net/LocalHost.cs`: 서버 시작(최소 인원 1, HostStarts)과 UPnP(백그라운드 스레드), 내부·공인 주소와 포트 상태를 맡는다. 닫을 때는 서버를 멈추고(최대 1초), 공유기 포트를 지운다(백그라운드, 게임을 끌 때만 최대 2.5초 기다림).
- `GameBootstrap.HostGame()`: 서버를 열고 `127.0.0.1:포트`로 접속한다. 포트를 못 열면(다른 프로그램이 사용 중 등) 접속 화면에 이유를 보인다.

### 방장 '시작' (프로토콜 v13)
- `StartRequest`(53, 클라이언트 → 서버, 내용 없음), `RoomInfo.flags` bit1 = 방장이 시작하는 방.
- `RoomConfig.HostStarts`: Waiting에서는 방장의 `RequestStart`를 받은 다음 틱에만 Countdown이 된다(최소 인원 이상일 때). 방장이 아닌 사람, Waiting이 아닐 때, 이 모드가 아닌 방의 요청은 무시하고 로그만 남긴다. 인원이 모자랄 때 누른 것은 기억하지 않는다.
- 콘솔 서버 `--host-start`로 같은 방식을 켤 수 있다(시험용).

### UPnP (`Shared/Server/UpnpPortMapper.cs`, `LocalAddress.cs`)
- 라이브러리 없이 직접 구현했다(저장소 규칙: 높은 수준 네트워크 라이브러리 금지). 순서는 이렇다.
  1. SSDP M-SEARCH(UDP 멀티캐스트 239.255.255.250:1900)로 공유기를 찾는다.
  2. 장치 설명 XML을 HTTP GET으로 받아 WANIPConnection(없으면 WANPPPConnection) 서비스를 찾는다.
  3. SOAP으로 `GetExternalIPAddress`, `AddPortMapping`(TCP, 같은 포트, 기한 없음)을 부른다. 기한 없음이 거절되면(724·725) 7200초로 다시 시도한다.
  4. 같은 포트가 이 PC로 남아 있으면(예전 비정상 종료) 지우고 다시 연다.
- 방을 닫을 때 `DeletePortMapping`으로 지운다.
- 공인 IP는 공유기에게만 묻는다. 외부 'IP 확인' 사이트는 쓰지 않는다(방장의 IP를 제3자에게 보내지 않기 위해).
- 내부 IP는 인터넷 쪽으로 나가는 인터페이스의 주소다(UDP 소켓을 8.8.8.8:53에 connect만 하고 보내지 않음).

### 화면
- 접속 화면(`ConnectView`): 이름, 캐릭터, **방 만들기**와 오프라인 미리보기, 그 아래 "친구 방에 참가" 줄(주소 칸 + 참가). 이름이 비면 두 버튼 다 꺼지고, 주소가 비면 참가가 꺼진다.
- 대기 화면(`LobbyView`): 상태 띠에 시작 버튼(방장만), 방장 PC에는 주소 칸.
- 접속 오류 문구를 '서버' 대신 '방장(PC)/방'으로 바꿨다. 예: 연결 거부 → "그 주소에 열린 방이 없습니다", 시간 초과 → "주소와 방장의 포트포워딩을 확인하세요", 서버 종료 → "방이 닫혔습니다".
- 실행 인자: `-host`(켜자마자 방 만들기), `-autostart`(방장이면 바로 시작), `-port N`(방 포트, 기본 7777). 예전 `-server … -autoconnect`도 그대로 쓴다.

### Store 패키지
- 매니페스트 기능을 `internetClient`에서 `internetClientServer` + `privateNetworkClientServer`로 바꿨다. 방을 열어 친구의 접속을 받기 때문이다.
- 들어오는 TCP 7777을 허용하는 방화벽 규칙(`desktop2:FirewallRules`, Client.exe)을 넣었다. Store로 설치하면 Windows 방화벽 창이 뜨지 않는다. 포트는 `store_config.json`의 `gamePort`.

## 3. 직접 돌려 보기

- 방장: 게임을 켜고 **방 만들기** → 대기 화면의 주소를 친구에게 알려 준다 → **시작**.
- 친구: 주소 칸에 그 주소를 넣고 **참가**.
- 한 PC에서 시험:
  ```
  Client/Build/Windows/Client.exe -host -port 7808 -name Host
  dotnet run --project Tools/BotClient -- --port 7808 --count 3
  Client/Build/Windows/Client.exe -server 127.0.0.1:7808 -autoconnect -name Guest
  ```
- 콘솔 서버로 같은 방식: `dotnet run --project Server/GameServer -- --port 7808 --min-players 1 --host-start`.
- 직접 빌드한(패키지가 아닌) Client.exe로 방을 만들면 Windows 방화벽 허용 창이 뜬다. 같은 PC 시험만이면 취소해도 된다.

## 4. 확인한 것과 못 한 것 (2026-11-11)

확인한 것
- `dotnet build` 경고 0, `dotnet test` **전부 통과**. 서버를 옮기기 전에 있던 252개, 새 `PlayerHostTests` 8개, 보조 에이전트가 쓴 `UpnpTests` 36개(파싱·HTTP·SOAP·사설 대역).
  - `PlayerHostTests`에는 실제 `GameServer`를 TCP 7809로 띄워 보는 시험이 있다. 손님의 시작 요청은 무시되고, 방장의 요청은 RoundStart로 이어지는지 본다.
- Unity Windows 빌드 성공(서버 코드가 `Shared` 어셈블리로 함께 컴파일됨).
- 한 PC에서 끝까지(`artifacts/player-host/run.ps1`):
  - 방장 클라이언트: `-uitest -port 7808`. 버튼 클릭 자동 시험 **37개 모두 통과**. 방 만들기 → 대기(방장, 맵·교체 방식 버튼) → 시작 전에는 카운트다운이 없음 → 시작 → 라운드 → 결과 → 나가기.
  - 손님 클라이언트: `-server 127.0.0.1:7808 -autoconnect`. 대기 화면에 "방장이 시작하기를 기다리는 중", 시작 버튼 없음. 한 판을 같이 함.
  - 봇 2개도 같이 들어옴.
  - 방장이 나가자 손님은 "방이 닫혔습니다 (방장이 나갔을 수 있어요)"와 함께 접속 화면으로 돌아감. 봇도 끊김.
  - 방장 로그에 접속자 IP가 없음(`conn N accepted`만).
- 서명 없는 시험 MSIX를 설치해 봄(`store.md` 15장).
  - Windows 방화벽에 "Jelly Survival Party" 규칙(Inbound TCP 7777, 설치 폴더의 Client.exe)이 생김.
  - 패키지 안에서 `-host -autostart`로 방을 열어 혼자 시작했고, 봇 2개가 LAN 주소 172.24.1.5:7777로 들어와 함께 진행됨.
  - 제거하면 규칙도 사라짐.
- 화면: 접속 화면(방 만들기·참가 줄, 영어 안내가 카드 안에서 줄바꿈), 방장 대기 화면(주소 칸·주소 복사·시작), 손님 대기 화면을 눈으로 확인. 한국어·영어 모두.

못 한 것
- **실제 UPnP 공유기**: 이 PC의 네트워크에는 SSDP에 답하는 장치가 없다. 그래서 확인한 것은 "공유기 없음 → 자동으로 열지 못함 + 포트포워딩 안내"뿐이다. 포트 열기·공인 IP·닫기는 단위 테스트(가짜 응답)로만 확인했다.
- **다른 집(인터넷 너머)에서 참가**: 이 PC 하나와 같은 LAN 주소로만 시험했다.
- 방화벽 규칙이 없는 일반 빌드(Client.exe)로 방을 만들 때 뜨는 Windows 방화벽 창은 시험 중에 따로 확인하지 않았다.

## 5. 남은 위험

- **UPnP를 실제 공유기에서 확인하지 못했다.** 이 PC의 네트워크는 SSDP에 아무 장치도 답하지 않는다(UPnP 꺼짐 또는 멀티캐스트 차단). 그래서 확인한 것은 이 둘뿐이다: 파싱·HTTP·SOAP 단위 테스트, "공유기 없음" 경로.
- 통신사 공유기 뒤에 집 공유기가 또 있거나(이중 NAT), 통신사가 사설 IP(CGNAT)를 주면 UPnP가 성공해도 밖에서 들어올 수 없다. 화면은 공인 IP가 사설 대역일 때만 이것을 알아챈다.
- 친구가 방장의 공인 IP를 알게 된다(주소를 직접 주고받는 방식이라 피할 수 없다). 처리방침에 적어야 한다.
- 통신은 여전히 암호화하지 않는다.
