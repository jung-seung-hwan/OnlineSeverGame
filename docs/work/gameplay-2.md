# 2차 게임플레이: 대시 쿨다운·밟기·엎드리기·움직이는 오브젝트

담당 세션: `[OnlineSeverGame] 조작·상호작용 추가 · 01`
기준: `.vibe-local/progress.md` '확정 사항 5' (2026-10-27 사용자 확정). 확정된 수치는 다시 정하지 않았다.
프로토콜: **v2** (`docs/protocol.md`). v1 클라이언트·서버와는 접속이 거부된다(버전 불일치).

## 1. 어떻게 플레이되는가

| 조작 | 하는 일 |
|---|---|
| ← → / A D | 이동 (엎드린 채면 느리게) |
| ↑ / W / Space | 점프 |
| Shift / J | 대시. **2초에 한 번**. 내 캐릭터 이름표 아래 게이지가 차오르고, 다 차면 하늘색 = 대시 가능 |
| ↓ / S (누르고 있기) | **엎드리기**. 땅·발판·상자 위에서만. 몸이 납작해지고(판정 높이 60%) 천천히(40%) 움직이며, 대시에 맞아도 반만 밀린다 |
| ↓ 누른 채 점프 | 발판 아래로 내려가기 (예전에는 ↓만 누르면 내려갔다). 바닥·상자 위에서는 그냥 점프 |

- **밟기**: 떨어지면서 다른 젤리 머리에 닿으면 상대가 1.5초 동안 납작하게 눌려 꼼짝 못 하고, 나는 위로 통통 튕긴다. 이미 기절한 상대를 또 밟으면 튕기기만 하고 기절 시간은 늘지 않는다(계속 밟아 영원히 묶어 두지 못한다).
- **버터 블록(밀리는 오브젝트)**: 가운데 높은 발판 아래에 하나. 걸어서 밀면 천천히 밀리고, 대시로 치면 대시가 거기서 멈추고 블록이 약 5유닛 미끄러진다. 위에 올라설 수 있고(올라탄 채 블록이 밀리면 같이 간다), 칼도 블록 윗면에 꽂힌다. 미끄러지는 블록에 부딪히면 같이 밀려난다. 라운드마다 제자리로 돌아온다.
- **흔들리는 장식**: 왼쪽 선반 아래 수건, 오른쪽 선반 아래 국자, 냄비 뚜껑 아래 마늘, 왼쪽 바닥의 허브. 지나가거나 부딪히면 그 속도만큼 흔들리다 멈춘다. 화면 장식일 뿐 판정은 없다(서버는 모름).
- 젤리 표현: 새 그림 없이 기존 스프라이트를 발밑 기준으로 세로로 누르고 가로로 조금 넓힌다. 엎드림 60%·가로 115%, 밟혀 납작 40%·가로 135%(밀려남 동작 그림 사용). 부드럽게 눌렸다가 펴진다.

## 2. 대시 연타 문제: 원인과 근거

사용자 보고: "대시 키를 연타하면 계속 대시된다".

### 재현 방법
1. 서버에 대시 로그를 넣었다: `--verbose`면 대시마다 `dash #id tick T seq S gap G (repeated input)`, 라운드 끝 줄에 `dashes: N (min gap G ticks)`.
2. 클라이언트에 `-autoplay mash`를 넣었다: 사람이 연타하듯 0.1초마다 대시 키를 눌렀다 뗀다(실제 `InputCollector` 래치 → `ToButtons` → 입력 전송 경로를 그대로 탄다).
3. 클라이언트 5초 통계 줄에 `dashes pred= server= shown= remoteShown=`(예측이 시작한 대시 / 서버 스냅샷이 확인한 대시 / 화면에 대시 동작이 새로 시작된 횟수)를 넣었다.
4. **바꾸기 전 코드(쿨다운 20틱)**로 Unity 빌드 + 서버 + 봇 1로 2라운드.

### 결과 (변경 전, 2026-10-27)
- 서버가 연타 클라이언트(#2)에 적용한 대시 간격: **20~21틱마다 정확히 한 번**(`gap 20`, `gap 21`이 30번 넘게 이어짐). 쿨다운보다 짧은 간격은 0번. `(repeated input)`으로 적용된 대시도 0번.
- 클라이언트 통계: `pred=30 server=29 shown=30`. 예측·서버·화면 횟수가 같다(1 차이는 라운드 끝 직전 예측). 보정(mispredicts) 0.

### 결론
- 네트워크 경로(입력 래치, 서버 입력 큐의 '비면 마지막 버튼 반복', 예측 재시뮬레이션, 표시의 Dashing 판정)에는 **대시가 더 나가는 버그가 없었다**. 의심했던 '빈 큐 반복'은 PrevButtons 비교 때문에 눌림이 새로 생기지 않고, 로그에서도 한 번도 대시를 만들지 않았다.
- 원인 1: 쿨다운이 **1초(20틱)**라 연타하면 0.2초 대시 + 0.8초 걷기가 끝없이 반복돼 '계속 대시되는' 것처럼 보였다. 쿨다운을 알려 주는 표시도 없었다. → 확정대로 **2초(40틱)**로 바꾸고 게이지를 넣었다.
- 원인 2: 접속 화면의 **'오프라인 미리보기'에는 쿨다운이 아예 없었다**(`PreviewSession`이 대시가 끝나자마자 다시 대시를 허용). 미리보기에서 연타하면 정말로 끊김 없이 대시됐다. → 서버와 같은 2초 쿨다운·게이지를 넣었다.
- 변경 후 확인: 서버+봇 8, 2라운드에서 모든 플레이어의 최소 대시 간격 **40틱**(아래 5장). 클라이언트 연타(`-autoplay mash`)도 40틱(아래 5장).

## 3. 어떻게 구현했는가

### 공용 물리 (`Shared/Simulation/`)
- `GameConstants`: `DashCooldownTicks` 20→40, 밟기(`StompStunTicks` 30, `StompBounce` 700), 엎드리기(`CrouchHeight` 720, `CrouchMoveSpeed` 160, `CrouchKnockbackSpeed/Lift` 450/250), 상자(`PushableWalkSpeed` 200, `PushableDashSpeed` 700, `PushableFriction` 50).
- `PlayerState`: `Crouching`, `Stomped` 추가. `Height`가 엎드리면 720이라 `Bounds`(칼·밀치기·밟기 판정) 전부 낮아진다.
- `PlayerPhysics.Step(ref s, buttons, stage, boxes, out contact)`: 엎드리기(땅 위 + Down), Down+Jump 발판 통과(그 틱만 발판 무시 → 다음 틱엔 이미 발판 아래라 다시 안 걸림), 상자 옆면 막기·윗면 착지. 대시가 상자에 막히면 그 자리에서 끝난다. 이 부분은 결정적이라 클라이언트 예측도 똑같이 계산한다. 예전 3인자 `Step`은 상자 없이 그대로 쓸 수 있다.
- `DashCollision`: 엎드린 대상은 넉백 절반.
- `StompCollision.Resolve(before, after, ...)`: 틱 전 발 높이 ≥ 상대 머리, 틱 후 ≤ 상대 머리, 가로 겹침, 스스로 떨어지는 중. 찾기와 적용을 나눠 플레이어 순서에 상관없게 했다.
- `Pushable.cs`: `PushableState`(크기 포함), `BoxContact`, `PushablePhysics`(밀기 적용, 한 틱 이동: 마찰·중력·벽·다른 상자·앞의 플레이어 밀어내기·착지, 칼 착지 높이).
- `Stage`: `Pushables`(`PushableSpawn`), `Decorations`(`Decoration`: 종류 이름, 위치, 크기, 매달림 여부)를 선택 인자로 받는다. **다중 맵 세션은 각 맵 정의에 이 두 목록만 넣으면 된다**(사용법은 `docs/protocol.md` 7장).
- `KnifePhysics.Step`에 상자 목록 인자(칼이 상자 윗면에 꽂힘).

### 서버 (`Server/GameServer/GameRoom.cs`)
- 한 틱: 플레이어 스텝(틱 시작의 상자 기준) → 대시 밀치기 → 밟기 → 상자에 밀기 적용 → 상자 스텝 → 상자 위 플레이어 같이 옮기기 → 칼(상자 포함). `StepWorld()` 하나로 묶었다.
- 상자는 라운드 시작(Countdown)·Waiting 복귀 때 스테이지 위치로 돌아간다.
- 로그: 라운드 끝 줄에 `dashes (min gap) / stomps / crouch ticks / box dash hits / box walk-push ticks / box travel / box#1 위치`. `--verbose`면 대시·밀치기·밟기·상자 대시를 하나씩.

### 프로토콜 v2
- 스냅샷 플레이어 flags bit4 Crouching, bit5 Stomped (항목 크기 26바이트 그대로).
- 스냅샷 끝에 `u8 boxCount` + 상자마다 22바이트(`id, x, y, vx, vy, width, height`). 크기를 함께 보내 맵이 실행 중에 상자를 만들어도 클라이언트가 그릴 수 있다.

### 클라이언트 (`Client/Assets/Scripts/`)
- `NetworkSession`: 예측·재시뮬레이션에 최신 스냅샷의 상자를 넘기고, 같은 스냅샷의 다른 플레이어를 마지막 버튼으로 함께 굴려 밟기 튕김을 예측(`PredictStep`). 통계 줄에 `snaps=`(2.5유닛 넘어 순간이동한 보정), `predBounces=`. 비교용 `-nostomppredict`. 상자 보간(칼과 같은 100ms 늦게). 칼 예고의 꽂힐 높이에 상자 포함. 엎드림·납작·대시 쿨다운을 `PlayerRender`로. 진단: 대시 횟수 통계, 0.3유닛 넘는 보정은 서버 상태와 함께 로그.
- `PlayerView`: 엎드림·납작 눌러 그리기. `BoxView`: 버터 블록(도형). `DecorView`: 흔들리는 장식(스프링, 닿는 순간 속도만큼 툭). `WorldView`가 둘을 관리.
- `GameUI`: 대시 게이지(이름표 아래), 조작 안내 줄 갱신.
- `InputCollector`: 시험용 `-autoplay mash`(대시 연타), `-autoplay stomp`(쫓아가 머리 밟기).
- `PreviewSession`: 대시 쿨다운 2초·게이지, 엎드리기, ↓+점프 발판 통과.

### 봇 (`Tools/BotClient/`)
- 무작위 행동에 '가끔 0.5~2초 엎드리기', '가끔 ↓+점프'를 넣었다. `DodgeBrain`의 발판 아래로 피하기는 ↓+점프로 바꿨다.

### 결정과 이유
- **이미 기절한 대상은 밟아도 기절 연장 없음**: 튕김 체공은 약 0.7초라 1.5초 기절 동안 같은 사람이 다시 떨어질 수 있다. 밟을 때마다 기절을 새로 걸면 영원히 묶인다. 튕김은 그대로 준다.
- **밟기 예측은 밟은 쪽 튕김만**: 처음에는 밟기를 서버만 판정했는데, 실제 클라이언트로 밟아 보니 내 캐릭터가 상대를 지나쳐 바닥까지 떨어졌다가 다음 스냅샷에서 2~2.5유닛 위로 끌려 올라갔다(2.5유닛이 넘으면 부드럽게도 못 하고 순간이동). 그래서 클라이언트가 튕김을 예측한다. 첫 시도(최신 스냅샷의 상대를 서 있는 것으로 보고 검사)는 상대가 점프 중이면 자주 틀려 보정이 오히려 늘었다(라운드 2개에서 92번). 최종 방식: 최신 스냅샷의 다른 플레이어를 **마지막으로 누른 버튼 그대로** 내 예측과 같은 틱만큼 함께 굴리고(서버도 새 입력이 없으면 그렇게 굴린다), 서버와 같은 조건 `StompCollision.Lands(내 전/후, 상대 전/후)`로 검사한다. 상대 기절은 여전히 서버만 정한다. 비교 결과는 5장.
- **상자 예측**: 클라이언트는 최신 스냅샷의 상자를 고정 물체로 본다. 멈춰 있는 상자 위에 서기·옆면 막기는 서버와 똑같고, 상자가 움직이는 동안만 조금 보정된다.
- **갇힘 방지**: 이미 겹친 상자·플레이어는 서로 막지 않는다(빠져나갈 수 있음). 미끄러지는 상자가 사람을 벽에 몰면 상자가 멈춘다.
- **엎드리기 값**: 판정 60%·이동 40%·넉백 절반은 제안값 그대로 두었다. 사람이 해 본 뒤 조정할 것(바꾸면 이유를 여기 적는다).
- 장식·상자 그림은 아직 없다(단순 도형). 아트 세션이 그림을 만들면 `DecorView.Draw`/`BoxView`만 바꾸면 된다.

- 테스트 중 클라이언트 한 개가 시작 48초 만에 오류 없이 정상 종료됐다(로그는 Unity 정상 종료 순서, `-quitAfter` 전). 예전 세션 기록의 '창이 quitAfter 전에 꺼짐'과 같은 증상이고 다음 두 번의 실행(각 2라운드, 클라이언트 2개)에서는 재현되지 않았다. 원인 미확인.

### 사람이 직접 플레이해 확인할 것
- 대시 2초가 답답하지 않은지, 게이지가 눈에 잘 띄는지.
- 엎드리기 값(60%·40%·넉백 절반)의 손맛. 엎드린 상태로 칼은 피할 수 없다(칼은 바닥까지 지나감) — 의도대로인지.
- 밟기가 너무 쉬운지(봇 8명이 무작위로 뛰기만 해도 라운드당 120번 정도). 내가 밟을 때 튕김이 바로 보이는지, 점프 중인 상대를 밟을 때 끌려가는 느낌이 남는지(로컬 핑 17ms에서만 확인, 실제 네트워크 지연에서는 보정이 커질 수 있음).
- 버터 블록 미끄러지는 거리(약 5유닛)와 걸어 밀기 속도(초당 4유닛).
- 장식 흔들림 세기.

### 남은 일
